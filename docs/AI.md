# AI 챗봇

프로바이더의 모델 목록은 설치된 CLI에 직접 질의합니다. Codex는 `app-server model/list`의 전체 페이지, Grok은 `models`, Claude는 초기화 응답의 `models`를 사용합니다. **설치·모델 목록 새로고침**으로 다시 조회할 수 있으며 실행 파일 경로를 변경하면 이전 목록을 무효화합니다. 빈 모델은 CLI 기본값이며, 목록에서 확인되지 않은 저장 모델은 선택을 유지하되 미확인으로 표시합니다. 조회 실패 시 고정 목록이나 다른 앱의 캐시로 대체하지 않습니다. CLI 제공 목록은 해당 계정의 실제 추론 성공을 보증하지 않습니다.

Windows 앱의 **AI 챗봇** 탭에서 로컬 대화 읽기, 분석, 질문, 답변 생성과 자동 답장을 사용합니다.
Python은 필요하지 않습니다. C# 엔진이 SQLCipher 4 DB와 마지막 커밋까지의 WAL을 검증하고 메모리에서 조회합니다.

## 작은 창과 방별 페르소나

- 창은 490×760 고정 크기입니다. 상단 탭 오른쪽의 표시로 자동답장 가동 여부를 확인합니다.
- 탭 순서는 **자동답장 → 페르소나 → 프로바이더 → 대화분석**입니다.
- 자동답장 목록에서 방을 선택한 뒤 봇과 답변 방식을 고르고 **연결**을 누릅니다. 여러 방을 선택했다면 마지막으로 선택한 한 방에만 적용합니다. 그 방을 선택 해제하면 남은 방 중 마지막 선택 방을 사용합니다. 방 목록에 봇 이름과 답변 방식 **즉시 / 호출 / 맥락**을 칩으로 표시합니다. 미연결 방은 첫 번째 페르소나를 사용합니다.
- 호출어 답변 모드는 해당 방의 **@봇이름**만 사용합니다. 별도 호출어는 지정하지 않습니다. 이름·연결 변경은 다음 폴링부터 반영됩니다.
- 페르소나 3개를 봇 이름으로 구분하며 이름 옆 **이미지 첨부**로 자동답장 이미지 사용을 선택합니다. 같은 탭 안의 **이미지**에서 기준 이미지·감정별 후보를 생성하고 적용합니다.
- 자동답장은 폴링/카카오 ID/방 새로고침을 위쪽 한 줄에 두고, 넓어진 방 목록 아래에서 봇/답변 방식/연결을 한 줄로 설정합니다. 별도 채팅방 드롭다운과 설명 문구, 탭 전체 스크롤을 제거했습니다. 방이 많으면 목록 내부에서 스크롤합니다.
- 답변 방식은 방마다 따로 저장하며 **연결** 버튼으로 봇과 함께 적용합니다. 실행 중 변경은 다음 폴링부터 반영됩니다. 기존 설정에 방별 값이 없으면 이전 답변 방식을 유지합니다.
- 이미지 전송은 앱의 `WM_DROPFILES`와 HWND 전송 확인을 사용합니다. Computer Use·클립보드는 필요하지 않습니다. 실제 PNG 첨부 발송은 로컬 대화 기록으로 확인했습니다.

## 시작

1. 카카오톡과 원하는 방을 엽니다.
2. **AI 챗봇 → 방 새로고침**에서 방을 선택하고 **대화 읽기**로 문맥을 확인합니다.
3. **프로바이더**에서 CLI 실행 파일·모델·effort를 설정하고 저장합니다.
4. **페르소나**에서 봇 이름, 역할, 말투, 대화 성향, 추가 지침을 저장합니다.
5. **대화 분석**, **답변 만들기**, **질문하기**를 사용합니다. 답변 초안은 편집 후 **발송란으로 가져오기**로 옮깁니다. 가져오기만으로 전송하지 않습니다.

**JSON 저장**은 선택한 최근 문맥을 내보냅니다. Portable 버전에서 같은 파일을 가져올 수 있습니다.

## 옵시디언 지식베이스

기존 옵시디언 보관함의 Markdown 파일을 직접 연결합니다. 옵시디언 앱을 재구현하거나 번들로 설치하지 않으며, 추가 플러그인·API 키·벡터 DB 없이 동작합니다.

1. 상단 **API 옆 지식베이스 → 연결 설정**에서 봇과 보관함 또는 공유할 하위 폴더를 선택합니다. 폴더가 없으면 **새 보관함**으로 만듭니다.
2. **이 봇의 답변에 지식 노트 사용**을 켜고 **연결 저장**을 누릅니다. 기본값은 꺼짐입니다. **모든 봇에 같은 연결 적용**으로 공유할 수 있습니다.
3. **자료 추가** 또는 끌어놓기로 MD·TXT·PDF·DOCX를 넣습니다. **직접 쓰기**는 붙여넣기와 새 노트 작성을 지원합니다. 목록에서 미리 보고 **옵시디언에서 편집**으로 열 수 있습니다. 검색창에서 관련 발췌를 확인하며, 검색은 로컬에서만 실행합니다.
4. **대화분석 → 대화 분석** 결과를 검토·수정한 뒤 **요약을 노트로 저장**을 누릅니다. 분석 당시 페르소나의 현재 보관함 아래 `KakaoRelay/날짜-고유ID.md`에 방 이름·저장 시각과 함께 저장합니다. 원문 대화 전체는 저장하지 않습니다.
5. 옵시디언에서 노트를 편집하거나 새 `.md` 노트를 추가하면 다음 답변부터 검색에 반영됩니다. 저장한 요약도 검색 대상입니다. 자동답장마다 요약을 자동 저장하지는 않습니다.

자료 추가는 원본 파일을 이동·수정하지 않습니다. 추출한 텍스트를 `자료/원본이름-시각-고유ID/001.md` 형태로 저장하고, 5만 글자 단위로 나누어 검색 가능한 크기를 유지합니다. 같은 이름의 파일을 다시 추가해도 이전 자료를 덮어쓰지 않습니다. 여러 파일 중 실패한 파일은 결과에 이유를 표시하며 성공한 파일은 유지합니다. 취소 시 완료된 파일은 남고 처리 중인 문서는 공개되지 않습니다.

한 번에 50개, 파일당 20MB, 추출 내용 200만 자까지 허용합니다. TXT·MD는 UTF-8 또는 BOM이 있는 Unicode 파일을 읽습니다. PDF는 최대 200쪽의 텍스트를 [PdfPig](https://github.com/UglyToad/PdfPig)로 추출합니다. 스캔 PDF·이미지의 OCR, 문서 이미지·첨부·서식·위키 링크 대상 파일의 자동 복사는 지원하지 않습니다. Word는 `.docx`의 본문·표 텍스트를 읽으며 구형 `.doc`는 지원하지 않습니다. 새 보관함을 옵시디언에서 사용하려면 처음 한 번 ‘폴더를 보관함으로 열기’로 등록하세요. 노트 편집 연결에는 [Obsidian URI](https://help.obsidian.md/Extending+Obsidian/Obsidian+URI)를 사용합니다.

같은 페르소나에 연결된 방들은 같은 지식을 사용합니다. 다른 페르소나에는 별도 보관함을 지정할 수 있습니다. 연결한 폴더의 관련 발췌가 AI 프로바이더에 전달되므로 공유할 자료만 넣으세요. 답변에는 `[노트: 상대경로.md]` 출처 표시를 요청하며, AI 결과의 `knowledgeSources`에는 실제 전달한 발췌와 경로가 담깁니다.

검색은 제목·본문의 키워드 및 한글 2글자 조각을 비교하는 방식입니다. 의미 기반 검색이나 위키 링크를 따라가는 검색은 아닙니다. 요청마다 현재 파일을 읽으며, 지식 설정이나 선택된 발췌가 달라지면 AI 세션을 새로 시작해 예전 발췌의 재사용을 막습니다. `.obsidian`·`.trash` 등 점으로 시작하는 항목, 심볼릭 링크·정션, Markdown 외 파일과 256KB 초과 노트는 제외합니다. 보관함과 상위 경로도 실제 폴더여야 합니다.

요청당 최대 2,000개 노트·10,000개 파일/폴더 항목·약 1,600만 글자를 검사하며, 최대 6개 발췌·12,000자를 AI에 전달합니다. 한도를 넘으면 폴더를 좁혀 선택하세요. 읽을 수 없는 개별 파일은 건너뛰며, 연결한 보관함 자체가 없거나 열리지 않으면 오류를 표시합니다. Windows UI에서 연결·검색·요약 저장을 지원하며, Portable UI에는 전용 관리 화면이 없습니다.

### 대화 자동 정리

Windows 앱의 **지식베이스 → 대화 자동 정리**에서 대상 방(최대 20개)을 선택하고 설정을 적용합니다. 앱이 실행 중이면 1분마다 실행 시각을 확인하며, 기본 정리 주기는 30분(5~1440분 설정 가능)입니다. 자동답장과 독립적으로 동작하고 카카오톡에 메시지를 보내지는 않습니다. 새 대화가 없으면 AI를 호출하지 않습니다. **지금 정리**는 주기를 기다리지 않고 확인하며 처음 설정한 방의 과거 기록을 가져오지는 않습니다.

방을 새로 선택하거나 껐다 켜면 첫 조회의 마지막 메시지를 시작 기준으로 저장합니다. 앱 재시작은 기존 처리 위치를 이어갑니다. 보관함·발신 계정·방의 구독 ID가 바뀌면 별도의 시작 기준을 잡습니다. 방에 연결된 페르소나의 보관함에 저장합니다. 보관함의 ‘답변에 사용’ 설정은 검색 여부를 제어하며, 대화 자동 정리의 켜기/끄기는 별도입니다.

한 번에 최근 500개를 확인하고 아직 처리하지 않은 메시지 최대 100개를 순서대로 정리합니다. 이후 메시지는 다음 주기에 이어서 처리합니다. 원문은 메시지당 최대 3,000자로 제한하며 삭제·첨부·봇 발신 계정의 메시지는 제외합니다. 같은 계정으로 사용자가 직접 쓴 메시지도 제외되므로 다른 사람의 발언을 중심으로 축적됩니다. 500개 조회 범위를 벗어난 누락 가능성이 있으면 오류를 표시하고 처리 위치를 넘기지 않습니다. 이 경우 주기를 줄이고, 필요하면 방 선택을 해제·적용한 뒤 다시 선택해 현재부터 시작하세요. 앱이 꺼진 동안 별도 수집 서비스는 실행되지 않습니다.

설정된 프로바이더 순서로 JSON 요약을 요청하고 실패하면 다른 활성 프로바이더를 시도합니다. 새 대화에서 최대 20개 항목을 추출하며 근거 메시지 ID와 정확히 일치하는 인용문이 있어야 저장합니다. confirmed 분류는 **대화에서 명시적으로 확인한 발언**을 뜻하며 외부 사실 검증은 아닙니다. 모델의 분류·요약 오류 가능성은 남습니다. 계정 비밀은 요약하지 않도록 지시하며 전체 원문 대화는 노트로 저장하지 않습니다. 원문과 짧은 근거 인용은 선택한 AI 서비스로 전달됩니다.

자동정리는 다음 구조로 저장합니다. 확인된 프로젝트 이름이 없으면 `미분류 · 방 이름`으로 묶고 프로젝트를 임의로 추측하지 않습니다.

| 폴더 | 내용 |
| --- | --- |
| `01-프로젝트/` | 프로젝트별 목표·현재 상태·결정·할 일·지식 링크를 모은 노트와 개별 결정 노트 |
| `02-업무지식/` | 절차·규칙 등 반복 활용할 지식의 현재 내용 |
| `03-할일/` | 담당자·기한·상태 및 체크박스를 가진 개별 할 일 |
| `04-대화기록/` | 날짜·방별로 이번에 추가하거나 갱신한 내용과 근거 |
| `05-변경이력/` | 변경 전후 내용, 담당자·기한·상태, 각각의 근거 |
| `검토필요/` | 미확정 항목, 불명확한 충돌, 갱신 대상이 확인되지 않은 항목 |

항목마다 고유 ID와 Obsidian 속성(project, owner, due, status, source_room, created, updated)을 저장합니다. `todo/doing/blocked/done/cancelled`로 할 일의 상태를 구분하며 근거가 없는 담당자·기한은 미정입니다. 기존 관리 노트의 ID·출처·인용이 일치하고 새 대화가 명시적으로 변경을 확정한 `update`만 같은 노트에 반영합니다. 이름이 바뀌어도 ID와 파일 경로를 유지하며 변경 이력으로 연결합니다. 단순히 다른 주장이거나 확정 여부가 불분명하면 검토 대상으로 보관합니다. 일반 사용자 작성 노트는 자동 갱신하지 않습니다. **확인된 내용은 지식으로 바로 저장**을 끄면 전부 검토 대상으로 저장합니다.

제목은 `휴가 신청 절차`, `출시 일정 확정`, `결제 오류 수정`처럼 대상과 핵심을 드러내도록 생성합니다. `title` 속성과 본문 제목을 함께 저장하고, 제목이 바뀌면 이전 제목을 `aliases`에 보존합니다. 파일명은 프로젝트·처음 제목·고유 식별자를 조합하며 이후 링크가 깨지지 않도록 유지합니다.

태그는 Obsidian의 `tags` 속성에 `유형/할일`, `프로젝트/프로젝트명`, `상태/진행중`, `주제/배포`처럼 계층형으로 저장합니다. 유형·프로젝트·상태는 앱이 일관되게 생성하고, 주제는 모델이 기존 태그 목록을 참고해 1~5개를 선택합니다. 공백·대소문자 차이와 중복은 정규화하며, 상태 변경 시 예전 상태 태그를 교체합니다. 변경 전 제목과 태그도 이력에 남깁니다. 프로젝트 요약·대화 기록·검토 노트·변경 이력에도 제목과 유형 태그를 넣습니다. 기존 요약 전환 시에는 원래 제목을 보존하고 그 제목을 기본 주제 태그로 사용합니다.

각 관리 노트의 **직접 메모** 영역은 갱신해도 보존됩니다. 자동 관리 영역이나 속성을 사람이 직접 바꿨다면 기존 내용을 덮어쓰지 않고 정리를 중단해 충돌을 알립니다. 프로젝트 요약도 동일한 방식으로 보호합니다. 모델의 주제명·프로젝트 분류는 완벽한 의미 기반 병합을 보장하지 않습니다.

이전 버전의 표준 `자동정리/` 요약은 처음 처리할 때 항목별 노트로 전환합니다. 원본은 그대로 보존하고 전환 완료된 원본만 봇 검색에서 제외합니다. 형식을 인식하지 못하는 문서는 그대로 검색할 수 있습니다. `04-대화기록/`, `05-변경이력/`, `검토필요/`는 봇 검색과 앱의 현재 노트 목록에서 제외하고 옵시디언에서 확인합니다. 검색은 관련 프로젝트·업무 지식·할 일을 먼저 선택하며 현재 노트에 포함된 근거를 함께 제공합니다.

처리 위치·최근 실행 시각·주제별 해시는 `%LOCALAPPDATA%/KakaoRelay/knowledge-automation/`에, 항목 ID와 현재 상태·관리 영역 해시·전환 기록은 보관함의 `.kakaorelay/structured.json`에 저장합니다. 노트 작성 직전의 파일 변경 계획과 처리 위치를 함께 기록하므로 중간에 종료되어도 이미 쓴 파일을 중복 생성하지 않고 나머지를 복구합니다. 저장 전후 해시가 맞지 않으면 외부 편집을 보존하고 중단합니다. AI 실패·취소 시 처리 위치를 넘기지 않으며 실패는 다음 정리 주기에 재시도합니다. 자동 정리 상태는 별도 로그나 Git에 자동 업로드하지 않습니다. 보관함의 노트는 설정된 Git 백업 대상입니다.

## 자동 답장

**AI 챗봇 → 자동 답장**에서 폴링 간격(1~300초, 기본 5초)과 답변 방식을 선택합니다. 변경 내용은 자동 저장되며 가동 중에는 중지 후 설정을 바꿉니다.

- **즉시 답변**: 다음 폴링에서 발견한 새 텍스트 메시지마다 답변합니다.
- **호출어에만 답변**: 호출어로 시작하는 새 메시지에만 답변합니다. 기본 모드입니다.
- **대화 맥락상 판단 후 답변**: 각 새 메시지 시점의 최근 20개 메시지를 보고 봇이 답할 상황인지 판단합니다. 처음에는 `gpt-6-luna low`와 `grok-4.7 low`를 동시에 실행하고 먼저 유효한 판단을 낸 모델을 선택합니다. 같은 앱 실행 중 후속 판단은 선택한 모델을 사용하고, 실패 시 재비교합니다. 비활성 프로바이더는 제외합니다. 판단 실패·형식 오류는 발송으로 이어지지 않습니다.

내 ID, 호출어, 선택 방, 폴링 간격, 답변 방식도 설정 파일에 저장됩니다. 편집 후 약 0.7초에 자동 저장하고 직전 파일은 `.bak`으로 보존합니다. 실행 파일은 `artifacts/app`에 배포하며 설정 파일은 배포 폴더 밖에 유지합니다.

Windows에서 자동답장할 방을 개수 제한 없이 선택할 수 있습니다. **자동 답장** 목록에는 현재 별도 창으로 열려 있고 발송 대상을 구분할 수 있는 방만 표시됩니다. 방 새로고침 후 원하는 방을 클릭해 선택합니다. 시작할 때도 열린 창을 다시 확인해 닫힌 방을 목록에서 제외합니다. **내 사용자 ID**를 입력하고 방별 봇·답변 방식을 연결한 뒤 **시작**을 눌러야 켜집니다. 호출어 방식은 연결한 봇의 `@봇이름`을 사용합니다. 하단에 가동 중인 방 수, 각 방의 상태·경과 시간이 표시됩니다. 수동 분석은 별도로 사용할 수 있습니다.

- 시작할 때 기존 메시지를 기준점으로 잡고, 이후 상대방의 새 텍스트를 선택한 답변 방식에 따라 처리합니다.
- 답변할 메시지로 결정되면 바로 AI 답변을 생성합니다. 생성 중 상태는 앱에서 표시하고, 채팅방에는 준비 안내를 보내지 않습니다. 같은 방에서 이전 답변을 처리하는 동안 들어온 호출은 다음 확인 주기에 감지됩니다.
- 내 ID의 메시지·삭제 표시·비텍스트·과거 기록을 제외합니다. 한 번 확인한 호출은 반복 생성하지 않습니다.
- 같은 이름의 로컬 방이 여럿이면 시작하지 않습니다. 실제 전송 시에도 열린 창을 하나로 확인해야 합니다.
- 같은 방에서 여러 호출이 들어오면 메시지 순서대로 모두 처리합니다. 서로 다른 방은 별도 CLI 프로세스로 동시에 생성하며, 카카오톡 전송 단계는 직렬 처리합니다. 새 메시지가 최근 500개 조회 범위를 넘어 누락될 우려가 있으면 해당 방을 중지하고 표시합니다.
- 기존 발송 엔진의 초안 보호와 요청 ID 중복 방지를 사용합니다. 전송 결과가 불확실하면 중지하며 새 ID로 자동 재전송하지 않습니다.
- 트레이에서도 동작합니다. **중지**는 생성 프로세스도 취소하지만 이미 시작된 네이티브 발송은 결과 기록까지 마칩니다. 앱을 재시작하면 자동 답장은 꺼집니다.

## 저장과 전달

### 주기별 정리·전달

**AI 챗봇 → 정리감시**에서 새 규칙을 만들고 로컬 기록을 읽을 수 있는 방 중 감시할 방을 체크합니다. 자동답장 방 선택과 별도로 관리하며, 닫힌 방도 읽기 가능하면 선택할 수 있습니다. 전달받을 방과 주기(1~1440분, 기본 30분)를 지정한 뒤 **추가사항이 있을 때 전달**을 켜고 **적용**합니다. 여러 원본 방을 하나의 수신방으로 묶거나 규칙을 여러 개 만들 수 있습니다. 수신방은 열린 방 목록에서 선택하며 원본 방과 달라야 합니다.

처음 활성화하면 현재 마지막 메시지를 기준으로 잡고 이후의 새 대화만 처리합니다. 새 메시지가 없으면 AI를 호출하지 않고, 잡담이나 이미 전달한 내용뿐이면 전송을 생략합니다. 새 결정·요청·일정·진행 상황을 출처 방 이름과 함께 전달합니다. 최근 전달 항목 80개를 모델에 비교 자료로 제공하고, 같은 주제·출처의 동일한 현재 내용은 코드에서도 중복을 차단합니다. 의미상 중복 판정과 요약 정확도는 모델의 판단에 의존합니다.

앱 실행 중 15초마다 주기 도래를 확인하며 자동답장 시작/중지와 독립적으로 동작합니다. 자동답장 대상에서 방을 해제하거나 자동답장을 중지해도 정리감시는 유지됩니다. 원본은 로컬 기록을 읽을 수 있어야 하고, 수신방은 발송할 때 별도 창으로 열려 있어야 합니다. 수신방이 닫혀 있으면 생성된 요약을 보관하고 다음 주기에 다시 확인합니다. `[정리·전달]`로 시작하는 전달 메시지는 재요약하지 않습니다.

규칙별 처리 위치·최근 전달 내용·대기 중 요약·발송 요청 ID는 `%LOCALAPPDATA%/KakaoRelay/summary-forwards/`에 저장합니다. 재시작하면 이어서 처리하며, 발송 직전에 상태를 기록해 중단되거나 발송 결과가 불확실하면 자동 재전송하지 않습니다. 이때는 앱 발송 이력과 카카오톡을 확인한 뒤 규칙을 껐다 적용하고 다시 켜면 현재 시점부터 새로 시작합니다. 원본·수신방 변경도 새 기준으로 시작하며 주기만 변경하면 처리 위치를 유지합니다.

한 주기에 새 메시지 최대 100개를 정리하며 원문은 메시지당 최대 3,000자를 사용합니다. 남은 메시지는 다음 주기에 이어서 처리합니다. 한 방의 미처리 대화가 로컬 조회 한도 500개를 넘어갔을 가능성이 있으면 누락시키지 않고 오류를 표시하므로 주기를 줄여 주세요. 설정은 `summaryForwards`로 저장하며 초기에는 빈 목록입니다.

자동답장 방 목록은 화면이 표시되고 자동답장이 중지된 동안 2초마다 열린 창의 변화를 반영합니다. 새 창이 먼저 열리고 로컬 방 정보가 늦게 준비되는 경우 최대 30초 간격으로 로컬 목록도 다시 조회합니다. 기존 방 선택과 페르소나 연결은 유지합니다.

프롬프트, 설정 파일, 이미지 목록, 발송 이력, 진단 보고서, 대화 내보내기 및 HTTP JSON 응답은 한글을 `\uXXXX`로 치환하지 않고 UTF-8 원문으로 씁니다. 메시지 구분과 따옴표·줄바꿈 처리는 JSON 규칙을 유지합니다. 기존 방별 세션 식별자와 발송 중복 방지 해시는 유지합니다.

자동 답장은 답변 생성 → 답변 감정의 이미지 → 답변 텍스트 순서로 보냅니다. 페르소나의 이미지 첨부가 켜져 있으면 답변에 감정(기쁨·슬픔·놀람·화남·생각·응원)이 분명히 드러날 때 해당 감정의 채택된 이미지만 보냅니다. 해당 감정 이미지가 없으면 텍스트만 보냅니다. 특별한 감정 표현이 없는 neutral 답변은 그 방에서 오늘 첫 답장일 때만 기본 이미지를 보냅니다. 첫 답장이 감정 이미지 또는 텍스트만으로 나갔다면 이후 neutral 답변에는 기본 이미지를 붙이지 않습니다. 날짜는 컴퓨터의 현지 날짜이며, 방·계정별 첫 발송 기록은 로컬에 저장해 앱 재시작 후에도 유지합니다. 이미지 또는 텍스트 발송이 확인되기 전에는 첫 답장으로 기록하지 않습니다. 이미지 발송 결과가 불확실하면 뒤의 텍스트를 보내지 않고 중지합니다.

이미지 목록에서 후보를 선택한 뒤 **마젠타 투명화**를 펼치고 슬라이더 오른쪽 **적용**을 누르면 생성과 별개로 로컬에서 투명화합니다. 색상 허용 오차는 기본 30이며, 0은 정확한 `#FF00FF`만 제거합니다. 원본과 적용 상태를 유지한 새 PNG 후보로 저장하며, 캐릭터 내부의 마젠타도 투명화됩니다. 결과를 사용하려면 선택 이미지 채택을 누르세요.

이미지 생성에 전달한 프롬프트는 이미지별로 `library.json`에 함께 저장됩니다. 후보를 선택하고 **생성 프롬프트**를 펼치면 저장된 내용을 확인·복사할 수 있습니다. 투명화 후보도 원본 프롬프트를 유지합니다. 과거 기록에 프롬프트가 없으면 저장된 프롬프트 없음으로 표시합니다.

기준 이미지의 투명화본은 원본과 같은 캐릭터로 연결됩니다. 원본과 투명화본 사이에서 기준을 바꿔도 채택한 감정 이미지를 유지하며, 어느 쪽에서 만든 감정 후보든 채택할 수 있습니다. 새로 생성한 기준 이미지는 별도 캐릭터로 구분합니다. 이전 버전에서 만든 투명화 기준은 이미지 목록을 열 때 실제 픽셀 변환이 일치하는 원본이 하나일 경우 연결을 복구하고, 복구 전 목록은 `library.json.before-family-repair.bak`에 보관합니다.

이미지 생성은 **페르소나 → 이미지**에서 로그인된 CLI를 사용합니다. GPT는 Codex CLI의 `imagegen` 내장 도구, Grok은 Grok CLI의 `image_gen`/`image_edit` 도구로 생성·편집합니다. 앱은 이미지 API를 직접 호출하지 않고 API 키 입력도 받지 않습니다. 실행 파일 경로는 프로바이더 설정을 따릅니다. 기준 이미지는 감정 이미지 편집에 전달하고 결과를 PNG로 보관합니다. 도구 실패 시 API로 대체하지 않으며 기존 이미지와 선택은 유지합니다.

설정은 `%LOCALAPPDATA%/KakaoRelay/ai-settings.json`에 저장됩니다. 다른 OS에서는 .NET의 사용자 LocalApplicationData 경로를 사용합니다. 앱은 대화 키·복호화 DB·일반 분석 결과를 파일로 저장하지 않습니다. 사용자가 JSON 저장을 선택한 경우에만 대화 문맥을 내보냅니다.

생성을 누르거나 자동 답장을 시작하면 선택한 문맥과 페르소나가 해당 CLI의 AI 서비스로 전달됩니다. 실패 시 다음 프로바이더로 전환하므로 실패한 프로바이더에도 요청이 전달됐을 수 있습니다.

방·프로바이더·모델/effort·페르소나별 세션을 분리합니다. 페르소나와 고정 지시문은 해당 세션의 첫 요청과 컴퓨터 현지 날짜가 바뀐 뒤 첫 요청에만 전달합니다. 같은 날 정상적으로 재개한 세션에는 현재 요청·답변 대상·지식 발췌·추가 또는 변경된 메시지만 전달합니다. 앱 재시작 후에도 `앱폴더/data/providers/<프로바이더>/conversations`의 세션 ID·메시지 해시·마지막 지시문 주입 날짜를 재사용하므로 같은 날 중복 주입하지 않습니다.

페르소나·작업 모드·고정 지시문이 바뀌거나 새 세션을 시작하면 즉시 다시 전달합니다. 취소·실패, 지식 발췌 변경 등으로 세션을 초기화한 경우도 포함합니다. 기본 감정 이미지 발송 여부와 주입 날짜는 별도로 관리합니다. 세션이 없는 단발 실행에는 매번 필요한 지시문을 전달합니다. 대화 내용은 각 CLI의 세션 기록에 보관되며 자체 보관 정책을 따릅니다. 이 변경은 매 요청의 지시문 중복을 줄이며, 재개 시 과거 문맥 처리 비용 자체를 없애지는 않습니다.

Codex 대화는 `app-server --stdio`, Claude 대화는 `--input-format stream-json --output-format stream-json`으로 방별 프로세스를 유지합니다. 같은 방의 후속 호출은 살아 있는 연결에 추가하고, 앱 재시작 후에는 저장된 ID로 복원합니다. 중지·시간 초과·통신 실패는 해당 연결만 폐기합니다. 실패 시 서비스가 다음 프로바이더로 전환하며, 2회전째 같은 프로바이더를 다시 시도하면 실패한 세션을 재사용하지 않고 전체 문맥으로 새 세션을 시작합니다. 직접 중지는 재시도하지 않습니다. 앱 종료 시 상주 프로세스도 종료합니다. 10분 이상 사용하지 않은 연결은 다음 요청 때 정리됩니다. 모델과 effort는 기존 프로바이더 설정을 그대로 사용합니다. Claude는 CLI 로그인이 필요합니다.

Grok 1.0.41의 `grok agent stdio` ACP에서도 연속 입력과 `session/load` 복원을 실제 확인했습니다. ACP는 CLI의 effort 인자 대신 `session/set_config_option`으로 `reasoning_effort`를 명시해야 했습니다. 이번 변경에서는 Grok의 기존 요청별 실행·resume 경로를 유지하고 상주 기능의 지원 여부만 검증했습니다.

프롬프트는 셸 명령으로 조립하지 않습니다. Codex/Claude에는 stdin, Grok에는 요청별 임시 파일로 전달하며 임시 파일은 종료 후 지웁니다. 작업 폴더는 방별 세션 폴더로 분리합니다. 취소/제한 시간 도달 시 자식 프로세스까지 종료합니다. 대화는 인용 데이터로 표시하고 삭제 본문은 새 분석 입력에서 제외합니다. 이미 CLI에 전달한 과거 내용은 세션 이력에 남을 수 있습니다.

## 웹검색과 대화 중 이미지 생성

Codex는 `web_search="live"`, Grok은 `web_search,web_fetch`, Claude는 `WebSearch,WebFetch`를 허용합니다. 최신 정보나 검색 요청에는 검색을 사용하고 답변에 출처 URL을 넣도록 안내합니다. 셸 실행이나 개인 MCP 연결은 추가하지 않습니다. Codex 설정은 [공식 설정 문서](https://learn.chatgpt.com/docs/config-file/config-reference)의 웹검색 항목을 따릅니다.

Windows 챗봇에서 현재 답변 대상이 새 그림을 요청하면 시각적 설명을 별도 CLI 이미지 생성기로 전달합니다. 답변 프로바이더가 Grok이면 Grok → Codex, Codex/Claude이면 Codex → Grok 순서로 사용 가능한 프로바이더를 최대 두 바퀴 시도합니다. 이미지 모델은 페르소나 이미지 관리의 기존 GPT/Grok 모델 설정을 사용합니다. Claude도 이미지 생성 자체는 Codex/Grok CLI에 맡깁니다. API 키나 직접 이미지 API는 사용하지 않습니다.

그림 요청의 자동답장은 **그릴 장면·구도·스타일 설명 전송 → 설명 전송 결과 확인 → CLI 이미지 생성 → 이미지 전송** 순서로 처리합니다. 생성 전 설명은 '이런 모습으로 그려볼게요'처럼 앞으로 할 작업을 말하며, 이미 완성했다고 말하지 않습니다. 설명 발송이 불확실하거나 중지하면 생성을 시작하지 않습니다. 생성이 끝나면 설명을 반복하지 않고 이미지만 보냅니다. 생성에 실패하면 별도 요청 ID로 실패 안내를 보내며, 이미지 발송 결과가 불확실하면 자동답장을 중지합니다.

생성 결과는 경로·파일 시각·크기·이미지 디코딩 검증 후 `앱폴더/data/providers/<프로바이더>/generated-replies`에 PNG로 보관합니다. 발송은 공용 대기열을 사용합니다. 명시적인 그림 요청은 감정 이미지 첨부 설정이나 오늘 첫 답장 여부와 관계없이 처리하며, 그 답변에는 감정 이미지를 추가로 붙이지 않습니다. 일반 답변의 감정 이미지는 기존처럼 텍스트보다 먼저 보냅니다.

대화분석/수동 질문의 생성 결과는 자동 발송되지 않습니다. `POST /v1/ai/generate`는 기존처럼 생성 완료 후 결과를 반환하며, `reply`/`chat` 결과의 `imagePath`를 `POST /v1/send-image`로 보낼 수 있습니다. `imagePrompt`는 그림 설명, `imageError`는 생성 실패의 진단 정보입니다. 자동답장만 설명 발송 후 이미지 생성을 시작하도록 두 단계로 처리합니다. Portable은 웹검색을 지원하며, 새 이미지 생성·카카오톡 발송 연결은 Windows 앱에서 제공합니다.

## Codex 대화와 Grok 백그라운드 위임

프로바이더 탭의 **Codex 대화 · Grok 백그라운드 위임**을 켜면 자동답장의 대화 담당은 설정된 Codex 모델입니다. Codex를 `gpt-6-luna`, Grok을 원하는 전문 작업 모델로 설정할 수 있습니다. 일반 대화는 Codex가 직접 답하며, 어려운 코딩·복잡한 분석·심도 깊은 요청만 모델이 판단해 Grok에 맡깁니다. 고정 키워드로 분류하지 않습니다. 이 모드의 대화 응답은 Grok으로 자동 대체하지 않습니다.

위임 접수 안내를 발송하고 결과를 확인한 뒤 작업을 별도 대기열에 넣습니다. Grok은 방의 대화 세션과 잠금을 사용하지 않으므로 같은 방의 새 메시지에 Codex가 계속 답할 수 있습니다. Grok 실행은 앱 전체에서 최대 2개씩 진행하며 추가 작업은 기다립니다. 작업별 기본 제한 시간은 600초이고 API 설정 `grokTimeoutSeconds`로 10~1800초를 지정할 수 있습니다.

결과가 도착하면 Codex의 해당 방 세션에 원래 요청과 함께 전달해 검토·정리합니다. 최종 답변에는 원래 요청을 짧게 표시하며, 접수 안내와 다른 발송 ID를 사용합니다. 최종 정리 과정은 다른 Codex 대화 턴과 순서대로 처리됩니다. 위임 결과를 다시 위임하지 않으며 Grok 실패는 그 작업만 실패 처리합니다. 중지·앱 종료 시 남은 작업을 취소하고 종료를 기다립니다.

작업·이유·결과·상태는 `앱폴더/data/delegations`에 보관하고 `GET /v1/ai/delegations`로 확인합니다. 재실행 시 중단된 작업은 `interrupted`로 표시하며 자동 재실행·재발송하지 않습니다. 일반 생성 API와 수동 대화분석은 백그라운드 위임을 시작하지 않습니다. 이 기능은 CLI의 분석·코드 응답을 반환하며 실제 저장소 수정이나 코드 실행은 수행하지 않습니다.

## 플랫폼 범위

Windows 로컬 읽기는 현재 키 문자열이 카카오톡 프로세스에 로드된 SQLCipher 4 파일을 지원합니다. 닫힌 방·예전 프로필·구형 암호화 형식 전체의 복구를 보장하지 않습니다. 키를 찾지 못하면 방을 연 뒤 새로고침하세요. 한 요청은 최근 1~500개 메시지이며 프롬프트는 최신 내용 위주로 약 6만 글자, 개별 본문은 8천 글자까지 포함합니다. 일부 문맥 생략 및 첨부 미디어 미분석을 고려하세요.

macOS/Linux는 [Portable](PORTABLE.md) 앱에서 가져온 대화를 분석합니다. 카카오톡 DB 직접 읽기·직접 전송·자동 답장은 Windows 어댑터 기능입니다.

## 프로바이더별 저장소

모든 CLI 작업은 실행 파일이 있는 폴더의 `data/providers/codex`, `data/providers/grok`, `data/providers/claude`를 사용합니다. 답변·맥락 판단·이미지 생성에 동일하게 적용되며, 설정·로그인 파일·로그·네이티브 세션과 방별 재개 메타데이터가 개인 CLI 저장소와 분리됩니다. 각 CLI의 실행 파일은 기존 설치 경로를 사용합니다.

처음 실행할 때 기존 파일 기반 로그인 정보만 복사합니다. Codex는 새 프로세스 실행 전 같은 계정의 더 최신 로그인 정보가 있으면 전용 저장소에 갱신합니다. 개인 MCP·플러그인·후크와 임의의 외부 저장 경로 설정은 가져오지 않습니다. 기존 KakaoRelay 방의 세션은 해당 방을 처음 사용할 때 그 방에 기록된 세션 ID로만 찾아 복사합니다. 가져올 네이티브 기록이 없으면 전체 최근 문맥으로 새 세션을 시작합니다. 원본 기록은 유지하며 개인 Codex 앱의 과거 목록을 자동 삭제하지 않습니다. 키체인에만 로그인 정보가 있는 환경이나 로그인하지 않은 CLI는 전용 저장소에서 별도로 로그인해야 합니다.

배포 시 `data` 폴더를 보존해야 합니다. 폴더에는 로그인 정보와 대화 기록이 있으므로 배포 패키지나 Git에 포함하지 않습니다. 새 컴퓨터에는 실행 파일을 배포하고 해당 컴퓨터에서 로그인합니다. macOS/Linux에서도 실행 파일 옆의 쓰기 가능한 `data` 경로를 사용합니다.

공식 경로 설정: [Codex CODEX_HOME](https://learn.chatgpt.com/docs/config-file/environment-variables), [Grok GROK_HOME](https://docs.x.ai/build/settings), [Claude CLAUDE_CONFIG_DIR](https://code.claude.com/docs/en/env-vars).

### 수신 첨부 읽기

자동답장과 정리감시는 수신 이미지·PDF 원본과 UTF-8 TXT·MD 본문을 AI에 전달합니다. 자동답장의 즉시 모드는 파일 메시지도 답변 대상으로 삼고, 호출 모드는 기존처럼 @봇이름 호출이 필요합니다(파일을 보낸 뒤 호출해 질문). 정리감시는 선택한 방의 새 첨부 내용도 근거에 포함합니다.

카카오 HTTPS 첨부 주소만 사용하고 리다이렉트는 따르지 않습니다. 크기와 SHA-1(제공된 경우)을 검증하고 서명 URL은 에이전트에 공개하지 않습니다. 원본은 `%LOCALAPPDATA%/KakaoRelay/attachments`에 캐시합니다. 파일당 20MB, 한 번에 최근 첨부 5개까지 전달합니다.

별도 OCR 엔진과 수신 PDF 텍스트 추출은 사용하지 않습니다. PNG/JPEG/WebP 이미지와 PDF는 원본 파일로 전달합니다. Codex 루나는 이미지를 native `localImage`로 받고 PDF는 원본 경로를 받아 로컬 도구로 직접 읽습니다. PDF가 있는 세션에만 shell 도구와 세션 작업 폴더 쓰기를 허용합니다. 필요할 때 에이전트가 페이지를 렌더링하여 확인하며 릴레이가 OCR/페이지 변환을 선처리하지 않습니다. 이미 읽은 PDF는 대화 기록을 재사용하며 PDF 존재만으로 Grok에 넘기지 않습니다. Grok는 요청별 임시 폴더에 복사된 원본을 `read_file`로 읽도록 요청하며 PDF 페이지 확인은 Grok가 처리합니다. Claude는 이미지/PDF를 base64 image/document 블록으로 받습니다. 지원 프로바이더가 없거나 읽기가 실패하면 내용을 읽었다고 처리하지 않습니다. TXT/MD는 UTF-8 본문을 전달합니다. 요약 근거에서 첨부 항목은 원본 메시지의 파일명/첨부 표기를 인용하며 첨부 내부 내용을 문자 단위로 검증한 근거는 아닙니다.
